## 2. 产品目标与范围

本产品用于监控 Nintendo eShop 中多款 Switch / Switch 2 商品在多个地区的价格，保存价格历史、换算人民币，并通过 Telegram 推送每日价格日报和官方确认的降价提醒。

首版支持完整游戏、Nintendo Switch 2 升级包，以及由管理员手动开启的 DLC、季票、豪华版、组合包和其他附加内容。

不在首版范围内：多用户注册、公开订阅、支付、移动 App。

当前唯一支持的仓库运行路径是 Node.js 22、PostgreSQL 17 与本地 Playwright Chromium。旧 Cloudflare Worker、D1、Cron 和 Browser Binding 已从仓库移除；线上 Cloudflare 资源仍待 NAS 等价验收后的独立退役授权。迁移不得减少本 PRD 的认证、订阅、五区采集、历史、设置、导出、通知和日区升级包能力。

## 3. 已确认功能需求

### FR-001 订阅与区域管理

- 支持订阅多款商品；每款商品可选择不同监控地区。
- 首次初始化时，管理员从美国、日本、墨西哥、巴西、香港五区中选择要启用的初始监控地区；至少选择一个地区。设置页可在之后启用其他任天堂 eShop 地区。
- 首次初始化时，管理员从已选初始地区中指定默认搜索区；后续可修改。修改只影响后续新增商品，不改变既有订阅。
- 添加流程：输入名称 → 搜索默认区候选商品 → 管理员确认 → 按设置中已启用地区自动匹配其他地区 → 处理无法可靠匹配的地区或明确跳过 → 创建订阅。默认搜索区只决定搜索入口，不会限制后续监控地区。
- 选择默认区官方候选后，向导可按官方标题、发行商和商品类型查询项目内已确认简体中文名称并预填；预填只是管理员体验，所有选中商品仍须各自提交非空中文名称。创建时 Node 必须重新读取官方锚点、按精确身份匹配词条，并只在未命中时接受该人工候选；浏览器标题、词条建议和在线翻译都不能取代此复核。
- 默认区搜索、跨区候选匹配和手动链接验证只使用任天堂官方商店或任天堂公开商品数据；第三方站点只可作为官方价格失败后的价格回退。
- 默认区候选支持一次选择多个不同商品，并由每个商品独立完成跨区确认、来源预览和订阅创建。
- 默认区官方搜索无结果、尚未通过地区适配器准入或候选不正确时，管理员可粘贴默认区任天堂官方商品链接。
- 搜索和跨区匹配阶段应从官方商品链接或公开商品数据自动取得每个地区各自的官方价格 ID；不得要求管理员手动填写价格 ID。
- 创建订阅前必须逐区告知官方价格状态：官方价格可用、官方价格 ID 未确认（并列出将使用的第三方站点）或无可用价格来源。管理员确认预览后才可创建订阅。
- 身份完全一致的跨区官方候选自动确认；自动匹配不可靠时，管理员可从当地候选列表选择、直接粘贴该区任天堂官方商品链接，或明确跳过该区。每个启用地区在创建前必须被确认或跳过，不能静默创建仅默认区订阅。
- 已验证的跨语言官方组合商品可自动确认，但必须同时满足：同为 `bundle`、同发行商、相同拉丁主标题、相同受控版本标记且本区候选唯一。美食家版当前准入英文 `Gourmet Edition` 与日文 `真の食通エディション`；当英文日区查询无同类型结果时，仅可从唯一官方同系列结果提取一个日文别名重试一次。日区最终复核以候选官方日文标题查询并继续绑定精确 URL 与价格 ID；原版、Switch 2 Edition、升级包、DLC 和季票不得因此规则自动匹配。
- 港区名称检索只请求可由服务端稳定访问的香港普通官网一次，不请求已验证会拒绝自动化服务端访问的 Magento 商城搜索。首轮没有同类型候选时，仅允许对已准入的 `Gourmet Edition` 或 Switch 2 Upgrade Pack 后缀生成一次基础标题搜索；结果必须为 1–5 个港区官方 `titles/{ID}` 本体。
- 港区基础本体详情只展开一层任天堂官方 `includedBundleItems`、`dlcItems.items` 和 `upgradeInfo` 关系，单根最多 50 个去重关联。组合商品、DLC 和升级包均须重新读取自己的 `bundles/{ID}` 或 `aocs/{ID}` 详情并验证地区、URL、类型和发行商；任一根或关联详情不完整时回退人工官方链接，不使用部分结果自动确认。
- 非日区 `automatic` 候选在最终写入前必须重新执行同一官方发现和唯一性规则，并仍得到完全相同的官方 URL；失效时整批零写入。人工选择不依赖该自动唯一性重验，日区继续使用其软件搜索与价格 API 专用复核。
- 每个地区商品记录匹配来源：自动匹配、手动选择或手动链接。
- 候选卡展示官方封面、标题、类型、发行商和官方可验证价格；存在促销时划线显示原价、显示折扣价及折扣力度。桌面端一行显示三个候选，点击整张卡片支持多选，选中状态仅以边框和背景表示。
- 取消订阅时仅停止后续采集和通知，保留既有价格历史；管理员可重新启用订阅。
- 永久删除是独立于取消订阅的不可恢复操作：仅管理员确认后才可批量删除指定订阅，并同时清理其地区映射、价格历史、采集日志、健康状态、通知事件、地区商品和游戏；不得删除其他订阅、全局汇率、设置或认证资料。
- 新建订阅时若识别为已订阅商品，不创建重复记录；应打开既有订阅编辑页。详情页提供“补全已启用地区”，以现有已确认地区商品为身份锚点并只原子新增缺失映射，不删除既有历史或配置。
- 日区升级包未作为独立名称搜索结果返回时，服务不得从 JavaScript 排队页猜测升级关系或商品 ID。既有隔离浏览器验证已连续三次从已验证的 `upgrade: 1` 根商品取得同一唯一官方 `アップグレードパス` URL；NAS Node 订阅流程使用本地 Playwright Chromium：点击“核验其他地区”后同步等待，最多用一个浏览器和三个全新无痕上下文串行解析三个商品。启动器只允许本地无头 Chromium，不提供远程端点、CDP、持久上下文、调试端口或用户数据目录；自动候选保存前必须重新证明根商品、唯一关系 URL 和 JP/JPY/在售/同 ID 价格。浏览器失败不自动重试，候选阶段按商品降级为重新核验或人工链接；人工链接在受控浏览器失败但官方 URL 和价格证据完整时只能以 `manual_link` 保存。本地浏览器不进入六小时价格采集、手动刷新、日报或历史查询。

### FR-002 数据来源与展示

- 任天堂官方商店为首选数据源。
- 官方读取失败时，按设置的优先级读取已启用第三方站点。
- 默认候选并排序的第三方站点：eShop-Prices、NT Deals；Deku Deals、Green Pipe 作为可选站点，由管理员启用、停用和排序。各来源须先通过 [ADR-002](../decisions/ADR-002-price-provider-validation.md) 的分区准入验证，才可在生产采集默认启用。
- 有官方价格时必须展示官方价格；无官方价格时可展示第三方价格，并在价格后清楚标记来源。
- 已确认的官方价格 ID 只能用于同一地区；官方接口响应的地区、货币或价格 ID 不匹配时，必须拒绝该官方结果并按设置回退。后续补齐官方价格 ID 只影响新快照，既有第三方历史保留原来源标记。
- 所有来源失败时，保留最近一次成功价格，显示“数据可能过期”与最后成功获取时间。
- 始终显示地区原始货币价格；人民币价格采用每日一次的中间汇率换算，并在当天统一使用同一批汇率。
- 系统使用内置的可靠汇率服务自动读取每日中间汇率，并展示汇率来源及更新时间。
- 当日汇率读取失败时，沿用最近一次成功汇率，并标记“汇率可能过期”；日报仍正常发送。
- 美区同时展示未税标价及含税估算价；初始税务州为俄勒冈州（无州销售税），可在设置中选择其他州。

### FR-003 价格采集、历史与手动刷新

- 自动采集频率为每 6 小时一次。
- 管理员可手动刷新；当前每次已认证点击都在该请求内同步执行一次与自动采集相同的官方采集轮次并返回统计，同时仅记录最近刷新时间。没有冷却、队列或调度器认领；六小时自动采集独立运行。未来恢复冷却必须另行确认并先增加相应测试和文档。
- 默认永久保留历史价格；设置可切换为仅保留最近一年或两年，并自动清理超期数据。
- 设置页支持无认证 HTTP、HTTPS、SOCKS5 代理的协议、主机和端口；不接受用户名、密码、PAC 或带认证的完整 URL。读取型任天堂/汇率请求在代理传输失败时最多直连一次，Telegram 等非幂等投递只在确定未发出时回退，浏览器核验则必须清理旧实例后才可直连一次。
- 代理连接测试只使用当前未保存草稿和服务端固定官方目标，分别显示普通 HTTPS 与浏览器 HTTPS 的“代理成功 / 直连回退成功 / 全部失败”三态；不得回显端点、响应正文或底层错误。
- 每条历史记录须保留采集时间、原始金额/货币、人民币金额/汇率、数据来源、价格口径和采集状态。
- 采集日志独立于价格历史，固定保留 90 天后自动清理。

### FR-004 官方降价提醒

- 仅当官方价格低于上一条官方成功记录时，触发即时降价提醒。
- 第三方价格用于展示和日报，不单独触发即时降价提醒。
- 同一采集轮次内的多个官方降价合并成一条 Telegram 汇总消息，按商品和地区分组。

### FR-005 日报与 Telegram

- 默认时区为 `Asia/Shanghai`，默认日报时间为每天 09:00；设置页可修改时区和时间。
- 全部订阅合并为一份日报，展示每款商品的全部监控区价格。
- Telegram 日报和即时降价汇总中，每款商品均展示历史最低价信息：最低价所在地区、当地货币金额、按当时汇率计算的人民币估算价及记录日期；多地区时同时展示各区各自的历史最低当地货币价格。
- 超出 Telegram 单条消息长度时，自动拆分连续消息并标注页码。
- Telegram 只支持部署环境变量，`TELEGRAM_BOT_TOKEN` 与 `TELEGRAM_CHAT_ID` 必须成对为空或成对提供。
- 设置页不填写、不保存、不回显 Telegram 凭据，当前也不提供会处理真实 Token 的测试消息入口；任何投递日志都不得包含 Token、Chat ID 或响应正文。

### FR-006 身份验证与恢复

- 当前仅限本机的功能开发阶段：仅在启动时显式设置 `LOCAL_DEVELOPMENT_AUTH_BYPASS=true`，进程会强制监听 `127.0.0.1`；除下述四个名称管理 API 外，其他管理 API 与页面才可直接进入，不要求密码、恢复码或 Cookie 会话。空库会自动写入五区默认公开设置，保证设置页与商品搜索可用，但不会写入管理员凭据、恢复码或会话。
- 名称管理是本机旁路的高影响例外：`GET /api/game-names?status=pending`、`POST /api/game-names/backfill`、`POST /api/game-names/suggestions` 与 `PATCH /api/game-names/:gameId` 在任何环境都必须提供有效 `session` Cookie 并通过服务端会话校验。批量回填会持久修改多个游戏的展示名称，人工保存还可能建立影响未来同身份游戏的复用词条，因此不得因本机开发开关而匿名读取或写入。
- 变量缺失或为 `false` 时，既有单管理员初始化、密码哈希、登录限流、会话与恢复码仍是访问控制；本阶段不继续设计密码登录体验。
- 此临时开关严禁用于 Docker、NAS、局域网或公网；完成业务功能后必须以独立需求重新设计、实现和验收认证恢复，才能进行任何部署验收。

### FR-007 网页信息架构

- 首页采用左侧导航布局。
- 左侧固定入口：仪表盘、添加订阅、价格历史、设置。
- 左侧导航底部显示 `package.json` 中的版本，格式为 `V x.y.z`。正式发布前必须在受审查的提交中显式把 `package.json` 与 lockfile 版本对齐到准备创建的 `vX.Y.Z`；当前工作流不会替维护者改写或校验该页面版本。普通本地构建、开发和测试不得修改版本，仓库不再使用自动递增补丁号的部署脚本。
- 仪表盘展示最新价格、当前最低价、下次日报/最近更新时间和手动刷新入口。
- 仪表盘中每款商品的地区价格固定按“美国区、墨西哥区、巴西区、香港区、日本区”展示；该顺序不受数据库写入顺序、跨区补全顺序或服务端返回顺序影响。未知未来地区排在已确认五区之后。
- 仪表盘游戏列表和订阅详情首行只使用服务端确认的简体中文游戏名。中文名仅来自项目内受控词表或已保存的人工中文名；未回填存量统一显示“待补充中文名称”，不得自动翻译、回退旧 `name_zh` 或展示任天堂官方标题。官方英文/地区标题仍保留在数据中，用于跨区身份复核、采集和管理员核对。
- 词条以“规范化官方标题 + 发行商 + 商品类型”的精确身份隔离，来源必须是发行商、中国大陆平台、香港参考或人工确认；管理员可更正单游戏名称，并仅在显式选择时将该确认提升为未来复用词条。目录回填只更新名称仍为空的同身份游戏，重复执行不覆盖人工名称且不会产生额外变更。
- 初始视觉主题为“温暖游戏库”（C）；设置页支持切换“沉稳深色”（A）、“清爽工具”（B）和“温暖游戏库”（C），并保存管理员主题偏好。
- 首版网页和 Telegram 推送仅使用简体中文。

### FR-008 数据导出

- 管理员可导出 CSV 格式的数据，范围包括订阅配置、价格历史和采集日志。
- 导出仅对已登录管理员开放。
- 导出内容不得包含管理员密码哈希、恢复码校验值、Telegram Token、Chat ID 或其他敏感配置。

### FR-009 采集异常通知

- 同一地区商品连续 3 次未能从官方或已启用第三方来源取得价格时，发送一次 Telegram 异常提醒。
- 后续恢复取得价格时，发送一次恢复通知。
- 异常提醒应包含商品、地区、连续失败次数、最近成功获取时间和最近错误摘要。

## 4. 非功能需求

- 所有敏感值（Telegram Token、恢复相关密钥等）不得以明文写入源代码、版本控制或普通日志。
- 数据来源和获取时间可追溯；第三方数据与官方数据必须在 UI 中可区分。
- 对外部商店和第三方站点的读取须具备超时、失败记录和限流保护。
- 临时网络失败可重试一次后再切换下一优先级来源；商品名称、发行商或类型校验不匹配时不得写入价格。
- 发布前必须在隔离 PostgreSQL 环境验证迁移、事务和调度；外部上线前还须以受控方式验证 Telegram、五区真实商品采集，并在生产部署后执行一次已认证手动刷新。真实凭据和响应不得写入测试报告。
- 页面以个人桌面管理场景为主，同时保持基本窄屏可用性。
- 唯一目标生产环境为 Synology DS423+ 上的 Docker Compose：一个 Node.js 应用容器提供前端、API、定时任务和本地 Playwright，一个项目专属 PostgreSQL 容器保存数据。仓库不维护 Cloudflare 双平台兼容层；线上 Cloudflare 资源只在完成等价验收并取得独立授权后退役。
- 本地 Apple Silicon M1 必须支持开发调试和生产形态 Compose 验收；正式 Git 标签由 GitHub Actions 在全部质量门禁通过后向 Docker Hub 公开仓库发布 `linux/arm64` 与 `linux/amd64` 多架构镜像。
- NAS 只通过固定镜像版本、Compose、未提交 `.env` 和随 Compose 分发的只读 PostgreSQL init hook 启动，不在设备上构建应用源码。首次 PostgreSQL 数据目录必须为空；init hook 仅在空目录引导期用独立 bootstrap 管理角色创建无集群级权限的普通应用角色，app 只取得普通角色 `DATABASE_URL`，不得取得 bootstrap 用户或密码。非空错误目录不会执行 hook，数据库健康检查必须阻止 app 启动。PostgreSQL 与 Chromium 调试端口不得向局域网暴露，数据库、Telegram 和认证秘密不得进入镜像层或仓库。
- NAS 使用全新 PostgreSQL 数据库，不迁移 D1 历史；必须提供版本化迁移、事务原子性、调度互斥、备份恢复和至少一个应用版本的回滚兼容窗口。
- 首阶段只验收局域网访问并保留完整单管理员认证。Cookie 始终使用 `HttpOnly` 与 `SameSite=Strict`；局域网 HTTP 必须显式 `COOKIE_SECURE=false`，未来接入可信 HTTPS 或 FRP 的 TLS 入口时必须设为 `true`。公网入口不属于本次迁移范围。

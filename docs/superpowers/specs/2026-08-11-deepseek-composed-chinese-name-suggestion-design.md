# DeepSeek 常用中文本体名与商品后缀组合建议设计

日期：2026-08-11
状态：用户已确认设计，待实施计划

## 背景

当前订阅向导只在管理员成功执行“核验其他地区”或“重新核验”后调用一次 DeepSeek，并把结果作为待确认草稿。请求已经限制为临时候选键、官方标题、发行商和商品类型，但固定提示词只笼统要求“常用简体中文名称”和保留版本后缀。

对于 `Overcooked! 2 - Nintendo Switch 2 Edition Upgrade Pack` 这类“已知游戏本体 + 版本/商品后缀”的标题，DeepSeek 网页版用自然语言提问可以回答，而当前结构化 API 请求可能返回 `low/null`。后端会把 `low`、结构异常和非法文本统一安全降级为 `null`，因此页面无法取得可预填名称。

## 目标

- 仍只在一次成功地区核验后调用一次 DeepSeek，不增加搜索、选择、编辑阶段的请求。
- 明确要求模型先识别游戏本体的常用简体中文译名，再组合完整商品后缀。
- 对已知本体且后缀明确的名称返回 `high` 或 `medium`，不因缺少官方来源证明而错误降级为 `low/null`。
- 保持 AI 结果仅为浏览器草稿，必须由管理员确认后才可进入既有保存流程。
- 保持现有字段白名单、固定官方 DeepSeek 地址、10 秒超时、严格 JSON 解码和异步过期响应保护。

## 非目标

- 不增加 DeepSeek 第二次重试或其他模型调用。
- 不让 DeepSeek 或服务端执行网页搜索，也不新增第三方搜索 API。
- 不建立模糊匹配的本地别名字典，不改变现有精确身份目录的复用规则。
- 不把 AI 建议声称为任天堂官方中文名称，不自动保存、发布或创建目录词条。
- 不放宽 `low/null`、重复键、控制字符、超长文本或畸形 JSON 的安全降级规则。

## 方案决策

采用“单次请求强化提示词”。DeepSeek 请求结构、端点、模型配置和响应外层协议保持不变，只增强固定系统提示词的任务定义、置信度口径、输出约束与少量示例。

没有选择“空结果后自动再问一次”，因为它会增加调用成本、等待时间与异步竞态。没有选择“本地本体别名字典 + 规则拼接”，因为它需要持续维护新游戏映射，并会把模糊本体关系引入当前严格身份目录之外。

## 数据流

1. 管理员在向导中唯一选择一个官方候选。
2. 搜索、候选选择和中文名称编辑不调用 AI。
3. 管理员点击“核验其他地区”或“重新核验”。
4. 地区核验成功且候选仍是当前选择时，浏览器只提交一个临时候选：`candidateKey`、`canonicalTitle`、可空 `publisher`、`productType`。
5. Node 从加密设置逐次读取 DeepSeek 凭据，向固定的 `https://api.deepseek.com/chat/completions` 发出一次请求。
6. DeepSeek 根据固定提示词返回 JSON。Node 只接受与输入键一一对应、格式合法且置信度为 `high` 或 `medium` 的 1–120 字符名称。
7. 浏览器仅在当前候选、当前请求代次且名称草稿尚未被人工编辑时预填，并显示“AI 建议，待确认”。

## 提示词合同

系统提示词必须明确以下语义：

- 任务是生成“常用简体中文名称建议”，不是证明任天堂官方命名。
- 先识别标题中的游戏本体，再处理版本、内容类型和商品后缀。
- 本体存在广泛使用的简体中文译名时优先使用该译名。
- `Nintendo Switch 2 Edition` 原样保留。
- `Upgrade Pack` 使用“升级包”；DLC、季票、合集等按常用简体中文商品表达处理。
- 版本和商品后缀属于完整名称，不能丢失、改成其他产品类型或并入本体造成歧义。
- 缺少官方来源证明不能单独成为 `low/null` 的理由，因为输出始终需要人工确认。
- 本体译名已知且后缀组合明确时返回 `high`；合理翻译但存在常见译名差异时返回 `medium`；只有本体确实无法可靠识别或翻译时才返回 `low/null`。
- 只返回既定 JSON，不输出解释、来源声明、Markdown 或额外文字。

固定提示词加入以下少量示例，约束模型理解而不建立运行时词库：

```text
DAVE THE DIVER Nintendo Switch 2 Edition
→ 潜水员戴夫 Nintendo Switch 2 Edition

Overcooked! 2 - Nintendo Switch 2 Edition Upgrade Pack
→ 胡闹厨房！2 - Nintendo Switch 2 Edition 升级包
```

示例不得影响候选关联键；实际输出仍必须复用请求中的临时 `candidateKey`。

## 响应与错误处理

- 合法 `high` 或 `medium`：预填输入框，显示“AI 建议，待确认”。
- `low`、`null`、候选键缺失/重复、字段非法、控制字符、空白或超过 120 字符：按当前候选返回 `low/null`，保留人工输入。
- 网络、超时、非成功 HTTP：继续返回固定脱敏错误，不显示 DeepSeek 响应正文或凭据。
- 管理员已输入任何草稿（包括空字符串编辑意图）时，迟到结果不得覆盖。
- 切换候选、重新搜索或发起新一轮核验后，旧结果不得写入新上下文或结束新请求的加载状态。

## 安全与成本边界

- 外发字段不变，不发送官方 URL、地区、价格、游戏/订阅 ID、Cookie 或数据库身份。
- Authorization 只发送到设置页允许的官方 DeepSeek HTTPS 地址，并继续拒绝重定向。
- 不记录 API Key、完整提示词、候选正文或供应商响应正文。
- 每次成功核验至多一次请求；搜索、选择、编辑、失败核验和其他自动流程调用次数为零。
- 不自动重试，因此最坏调用成本与当前实现一致。

## 测试设计

- 服务合同测试断言系统提示词包含“先识别本体再组合后缀”、置信度口径、`Upgrade Pack` 处理和两个固定示例。
- 使用 `Overcooked! 2 - Nintendo Switch 2 Edition Upgrade Pack` 的响应夹具，断言合法的“胡闹厨房！2 - Nintendo Switch 2 Edition 升级包”以非空 `high/medium` 建议返回。
- 保留并运行 `DAVE THE DIVER Nintendo Switch 2 Edition` 的非空回归。
- 断言请求仍只包含四个白名单字段，不包含 URL、地区、价格或持久化 ID。
- 页面回归继续证明：成功核验一次只发一次请求；搜索、选择与编辑不请求；人工草稿优先；切换候选和连续核验的旧响应失效。
- 现有 `low/null`、畸形 JSON、重复键、超长名称、控制字符、超时与非成功 HTTP 测试继续通过。

## 验收标准

- 选中 `Overcooked! 2 - Nintendo Switch 2 Edition Upgrade Pack` 并成功核验其他地区后，只调用一次 DeepSeek。
- 合规模型响应能够预填“胡闹厨房！2 - Nintendo Switch 2 Edition 升级包”。
- 预填明确标记为 AI 建议且不会自动保存。
- 当前安全、认证、外发字段和异步隔离测试全部保持通过。
- 完整测试、TypeScript、生产构建和差异检查通过。

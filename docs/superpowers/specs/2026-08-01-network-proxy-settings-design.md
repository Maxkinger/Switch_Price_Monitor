# 网络代理设置设计规格

状态：实施中；Task 1（PostgreSQL 无认证代理配置持久化）与 Task 2（Node 出站代理与安全回退）已完成，待提交

确认日期：2026-08-01

依赖：[NAS Docker 与 PostgreSQL 迁移设计规格](2026-07-27-nas-docker-postgresql-migration-design.md)

## 1. 目标与范围

在已登录管理员的设置页新增网络代理配置，使 NAS Node.js 运行时的全部外部网络访问可以优先通过管理员指定的代理。覆盖范围包括任天堂商品搜索、商品页与价格接口、汇率服务、已准入第三方价格来源、Telegram 发送，以及日区升级包使用的 Playwright 浏览器导航。

代理支持无认证的 HTTP、HTTPS 与 SOCKS5。启用代理后先尝试代理；代理连接失败时按本规格的安全边界自动尝试一次直连。设置页提供不保存草稿的独立连接测试，并明确区分“代理连接成功”“代理失败但直连成功”和“代理与直连均失败”。

本功能只进入已确认的 NAS Node.js 目标架构。当前 Cloudflare Worker 不增加临时代理网关、TCP 隧道或双运行时兼容层；功能实施顺序必须位于 Node 出站网络抽象建立之后、外部提供方全面接线和 NAS 功能等价验收之前。

## 2. 非目标

- 不把代理作为新的价格来源，也不改变任天堂官方与第三方价格来源的业务优先级。
- 不允许浏览器提交任意测试 URL，不把应用变成通用转发代理、端口扫描器或代理凭据读取接口。
- 不支持 PAC、系统代理自动发现、代理链、每个地区独立代理或按来源自定义代理。
- 不在 Cloudflare 生产环境实现常规 HTTP、HTTPS 或 SOCKS5 代理。
- 不在本阶段提供“禁止直连”的严格模式；已确认行为固定为代理失败后允许直连回退。
- 不通过代理设置改变 Telegram 的业务去重规则、任天堂商品身份校验、价格超时或第三方来源准入规则。

## 3. 方案与组件边界

采用集中式出站网络层。Node 依赖装配创建 `OutboundNetworkService`，外部 HTTP 客户端不直接读取数据库、环境变量或代理 URL，只调用该服务提供的 Fetch 兼容接口。服务负责读取一次代理配置快照、创建 HTTP/HTTPS/SOCKS5 连接器、执行受控直连回退、返回安全传输元数据，并在请求结束后释放连接资源。

任天堂搜索与价格、商品页、汇率、第三方来源和 Telegram 共享该 HTTP 边界。Playwright 不能复用 Fetch 连接器，但必须消费同一份代理配置和同一套失败分类，由独立浏览器适配器把 HTTP、HTTPS 或 SOCKS5 协议、主机与端口映射为 Playwright 代理选项。

配置更新只影响更新后开始的新操作。一次商品发现、采集轮次、Telegram 投递或 Browser Run 在开始时取得不可变配置快照；执行中修改设置不会让同一业务操作在新旧代理之间来回切换。

未采用以下方案：

- 各提供方分别解析代理：容易产生不同的回退、超时和脱敏行为，新增来源也可能绕过代理。
- 仅依赖 `HTTP_PROXY`、`HTTPS_PROXY` 等容器环境变量：无法满足设置页即时修改、SOCKS5、三态连接测试及 Playwright 一致接线。
- Cloudflare 外部代理网关：需要额外常驻服务和自定义转发协议，仍不能可靠覆盖 Browser Binding，且违背停止维护双平台兼容层的已确认方向。

## 4. 设置页与交互

现有 `/settings` 单页表单新增“网络代理”卡片，包含：

- “启用网络代理”开关。
- 协议下拉框：`HTTP`、`HTTPS`、`SOCKS5`。
- 主机与端口输入框。
- 独立的“测试连接”按钮。
- 固定提示：代理连接失败后系统会自动尝试直连，直连回退可能暴露 NAS 的出口地址。

关闭代理时仍保留已填写的协议、主机与端口，便于稍后重新启用；关闭状态下正常业务请求直接连接。管理员仍可在未启用前测试当前草稿，测试不会保存开关或其他字段。

测试结果分别展示“普通 HTTPS 请求”和“Playwright 浏览器”两项。每项只能是：

- `proxy-success`：代理完成连接并取得目标 HTTP 响应。
- `direct-fallback-success`：代理发生可回退传输失败，随后直连取得目标 HTTP 响应。
- `failed`：代理和直连均未取得目标 HTTP 响应。

页面使用对应的简体中文文案，并可附加 `proxy-authentication-required`、`dns`、`connect-timeout`、`tls`、`browser-launch` 或 `unknown-transport` 等安全错误类别；不展示堆栈、代理地址、目标响应正文或底层库错误。若代理返回 `407`，页面提示“代理要求认证，当前不支持”，随后仍按已确认规则测试直连。

## 5. API 契约与校验

### 5.1 公开读取模型

`GET /api/settings` 在既有公开设置中增加：

```ts
interface PublicProxySettings {
  enabled: boolean;
  protocol: "http" | "https" | "socks5";
  host: string;
  port: number;
  directFallbackEnabled: true;
}
```

`directFallbackEnabled` 是已确认运行规则的只读声明，不接受浏览器修改。响应模型没有用户名、密码、代理 URL 或任意认证字段。

### 5.2 保存模型

`PATCH /api/settings` 的代理字段使用：

```ts
interface ProxySettingsPatch {
  enabled: boolean;
  protocol: "http" | "https" | "socks5";
  host: string;
  port: number;
}
```

更新继续与设置页其他字段一次提交并在单个 PostgreSQL 事务中保存，避免公开字段与代理字段出现部分更新。请求体出现用户名、密码、嵌入式认证信息或未知代理字段时返回 `422`，不能静默接受后忽略。

### 5.3 连接测试

`POST /api/settings/proxy/test` 接受与 `ProxySettingsPatch` 相同的草稿，但不持久化。接口固定测试代码内置的两个 HTTPS 目标：普通客户端请求 `https://www.nintendo.com/robots.txt`，浏览器请求 `https://store-jp.nintendo.com/robots.txt`。目标返回任何完整 HTTP 响应均证明传输可达，但代理返回 `407` 必须分类为“代理要求认证，当前不支持”并触发直连测试。

接口只允许已登录管理员调用，采用独立短超时和并发互斥，避免重复点击堆积 Chromium 或外部连接。请求不能携带目标 URL、HTTP 方法或任意请求头；测试不读取商品、价格、Telegram 凭据或订阅数据。

### 5.4 输入约束

- 协议仅允许 `http`、`https`、`socks5`。
- 主机只接受规范化主机名、IPv4 或 IPv6，不接受 scheme、路径、查询、片段、空白、控制字符或嵌入式认证信息。
- 端口必须是 `1–65535` 的整数。
- 启用代理时主机和端口必须完整；关闭代理时保留的草稿也必须满足相同格式，防止重新启用时绕过校验。

代理主机允许指向管理员局域网中的地址，因为家庭 NAS 代理通常运行在同一网络；这一能力只对已认证单管理员开放。连接测试仍固定目标地址，因此代理主机可配置不等于浏览器可以要求服务端访问任意目标。

## 6. 持久化与安全边界

PostgreSQL `settings` 单例只保存代理开关、协议、主机和端口，不增加代理用户名、密码、密文或设置加密密钥。设置读取、CSV 导出和诊断接口仍使用显式字段白名单；代理主机与端口虽然不是认证秘密，也不进入普通运行日志或外部错误响应。

首版明确不支持代理认证。页面没有认证输入，API 拒绝认证字段，连接器也不从环境变量或 URL 读取代理账号。若管理员的代理要求认证，系统将其视为代理连接失败并按已确认规则尝试直连，而不是弹出凭据输入或猜测默认账号。

## 7. 出站请求与直连回退

HTTP 代理使用 `http://host:port`，HTTPS 代理使用 `https://host:port`，SOCKS5 使用代理端解析目标域名的模式，避免先由 NAS 本地 DNS 泄露外部目标。连接 URL 只在出站网络层由受校验字段构造，不进入日志或响应。

回退规则固定如下：

1. 代理握手失败、代理 DNS/连接/TLS 失败、`407`、连接阶段超时或连接器明确证明请求尚未发出时，允许直连一次。
2. 目标服务器已返回任何 HTTP 响应时，不因 `4xx` 或 `5xx` 改走直连；业务提供方继续解释该响应。
3. 任天堂、汇率和第三方读取等幂等请求发生无响应的传输失败时，允许直连一次。
4. Telegram 等非幂等发送只有在连接器明确证明请求字节尚未发给目标时才立即直连。请求已发出但响应超时或结果不明时不立即重发，事件保持原有待处理/审计语义，避免一次代理故障产生重复通知。
5. 调用方的 `AbortSignal` 已取消时不开始直连。代理与直连分别使用该提供方既有的单次超时，因此最坏执行时间可以是两个顺序尝试之和；业务任务的整体关闭宽限期仍是外层上限。

服务返回仅供内部诊断的传输路径 `proxy`、`direct` 或 `direct-fallback`。价格快照继续使用 `official` 或具体第三方站点作为业务来源；代理路径不得写入或替换价格来源字段。采集日志和结构化运行日志不得记录代理主机、端口、完整错误、连接 URL 或外部响应正文。

## 8. Playwright 行为

Browser Run 从同一配置快照创建 Chromium 代理选项。依据 [Playwright 网络代理文档](https://playwright.dev/docs/network)，HTTP、HTTPS 与无认证 SOCKS5 均直接映射为浏览器代理；不创建本地桥接器或代理服务。代理成功时继续沿用既有“一个活动浏览器、最多三个串行隔离上下文、每项三十秒”的规则。

若浏览器启动或首次固定官方导航发生可回退的代理传输失败，适配器必须依次关闭页面、上下文和代理浏览器，再启动一个不带代理选项的直连浏览器并从该商品步骤开头重试一次。代理与直连浏览器不能同时存在，也不能复用代理浏览器的页面、Cookie、缓存、存储或响应证据。启用直连回退后，一个业务请求最多出现两个顺序浏览器实例；第二个实例只允许用于代理失败回退，不改变每批三个商品和保存前二次官方复核边界。

页面解析失败、商品身份不匹配、候选不唯一、目标 HTTP 响应已取得后的业务失败，以及调用方取消均不触发直连浏览器。所有成功和失败路径继续等待资源关闭；日志只记录安全阶段与传输路径。

## 9. 测试策略

功能改动遵循测试先行，每个行为先观察预期失败，再实现最小代码。自动化测试使用本地 HTTP 目标与代理夹具，不依赖公网或真实代理凭据。

必须覆盖：

- 设置校验：三种协议、主机/IP、端口、控制字符、启用与关闭状态。
- 持久化：代理字段与其他设置的 PATCH 原子回滚，数据库迁移不创建认证、密文或加密密钥字段。
- API 边界：GET/PATCH/测试响应不含代理认证字段、完整连接 URL 或底层错误；未认证请求均返回 `401`，提交认证字段返回 `422`。
- 连接器：无认证 HTTP、HTTPS、SOCKS5 代理成功，代理要求认证、DNS、连接、TLS 与超时分类，目标 HTTP `4xx/5xx` 不回退。
- 回退：幂等读取只直连一次，取消不回退，Telegram 发送前失败可回退，发送结果不明不立即重发。
- 配置快照：执行中保存新设置不改变正在运行的请求或浏览器。
- Playwright：HTTP/HTTPS/SOCKS5 直连代理选项、代理失败后完整关闭再直连、业务解析失败不回退，以及任何路径无页面/上下文/浏览器泄漏。
- 页面：代理卡片、无认证字段、保存中状态、三态测试结果、`401` 清理与窄屏布局。
- 容器：M1 HTTP/HTTPS/SOCKS5 与 Chromium 冒烟，以及日志和镜像敏感信息扫描。

DS423+ 最终验收使用管理员提供的无认证临时测试代理配置，依次验证代理成功、故意不可达代理触发直连成功、关闭代理直接连接三种场景。验收不得把真实代理地址写入截图、日志或文档；完成后由管理员决定保留或清除配置。

## 10. 文档与实施顺序

本规格同步更新 PRD、需求追踪、系统架构、API、数据模型、质量验收、NAS 迁移规格和文档中心。后续实施计划必须把本功能作为 NAS Node 迁移的依赖任务拆分，至少包含：PostgreSQL 设置字段、统一 HTTP 出站层、现有提供方接线、Playwright 接线、设置 API 与页面、连接测试、容器配置和 M1/NAS 验收。

当前 Cloudflare 生产代码、D1 迁移和部署配置保持不变。任何本地提交前必须先向管理员说明精确变更范围并取得确认；确认后在同一操作中提交并推送。

# DeepSeek 中文游戏名称建议设计规格

**日期：** 2026-08-10
**状态：** 已实施；真实 DeepSeek 凭据与 NAS 部署验收待执行

## 1. 目标

在管理员完成新订阅的“核验其他地区”后，使用 DeepSeek 根据已经由任天堂官方数据确认的商品信息生成简体中文游戏名称建议，并自动预填名称输入框，供管理员编辑和确认。

该功能只缩短人工填写时间；AI 建议不是正式名称、不能直接写入词库，也不能影响官方商品身份、跨区关系、价格、地区或订阅创建决策。

## 2. 适用范围与明确排除项

适用范围：

- 新订阅向导在地区核验成功后，为每个已选默认区商品获取一次建议。
- 中文名称管理页为每个待补充游戏提供按需生成建议的操作。
- 管理员确认现有中文名称表单后，仍复用既有人工覆盖和可复用词条保存规则。

明确排除：

- 不调用 AI 或在线翻译来搜索、确认或改变任天堂官方商品身份。
- 不自动保存 AI 输出，不自动创建目录词条，不批量回填 AI 建议。
- 不把 DeepSeek API Key 保存到浏览器、设置页、PostgreSQL、日志、测试夹具或 API 响应。
- 不发送 Cookie、密码、恢复码、会话、Telegram 凭据、数据库连接串、价格、订阅 ID 或地区商品 URL 给外部服务。

## 3. 数据流与安全边界

```text
任天堂官方候选及跨区核验
        │
        ▼
服务端收窄的名称建议字段（短批内键、标题、发行商、商品类型）
        │
        ▼
DeepSeek 名称建议适配器（超时、批量上限、严格 JSON）
        │
        ▼
浏览器独立名称草稿（AI 建议，待确认）
        │ 管理员编辑/确认
        ▼
既有名称服务（精确 identityKey、词条优先级、人工确认）
```

已认证浏览器只提交当前页面持有的标题、可空发行商、商品类型和关联键；路由逐字段限制长度、控制字符、类型、批量和重复键，但不会把这些客户端字段提升为已验证的持久化官方身份。新订阅向导会为每次 AI 请求生成不含商品 URL 的短批内 `candidateKey`，并只在浏览器内把它映射回真实 UI 候选键；管理页使用现有短 `gameId` 关联单行响应。两种键都不能被当作数据库身份、目录身份或订阅 ID，DeepSeek 不会取得地区商品 URL；管理员最终保存仍由既有服务重新读取官方锚点。

在本机 `LOCAL_DEVELOPMENT_AUTH_BYPASS=true` 模式下，接口只继承既有的回环本机旁路；旁路缺失或为 `false` 时必须使用真实管理员会话。该行为不得扩大到 Docker、NAS、局域网或公网部署。

## 4. DeepSeek 适配器合同

服务器内部 `DeepSeekGameNameSuggestionService` 负责调用 DeepSeek Chat Completions JSON 输出模式。它接收一批 1–10 个名称建议候选，每项只含：

- `candidateKey`
- `canonicalTitle`
- `publisher`（可空）
- `productType`

提示词要求模型只提供常用简体中文名称建议，区分本体、DLC、升级包、季票与合集；没有把握时返回 `null`，不得猜测、编造来源或声称已经人工确认。

响应必须收窄为：

```ts
type AiChineseNameSuggestion = {
  candidateKey: string;
  displayNameZhCn: string | null;
  confidence: "high" | "medium" | "low";
};
```

服务端再次校验候选键一一对应、名称修剪后长度为 1–120 且无 C0/C1 控制字符，并只重建三个响应白名单字段、丢弃额外字段。重复统计先于其他字段筛选，因此同键即使一条畸形、一条有效也会整体降级；`low` 置信度、结构异常、重复/未知候选键或不合法文本均转换为该候选的 `displayNameZhCn: null`，不能让模型输出直接穿透到页面或数据库。

单次外部调用的超时为 10 秒，最大批量 10 项。网络、限流、DeepSeek 非成功状态、JSON 解析和超时都返回固定脱敏错误；向导保留地区核验结果和已有草稿，管理员可继续手工填写。服务端不记录 prompt、响应正文或 API Key。

## 5. HTTP 与配置合同

同源管理员端点：

```text
POST /api/game-names/ai-suggestions
```

请求只接受上述名称建议候选数组；响应返回同数目的受控建议数组。该端点不创建游戏、词条或订阅，也不调用任天堂、价格、汇率或 Telegram 服务。

`DEEPSEEK_API_KEY` 只通过服务器私有环境变量配置；可选 `DEEPSEEK_MODEL` 仅允许受控模型标识并提供安全默认值。当前设置 API 与设置页没有 AI 配置状态、读取、编辑或保存能力，也绝不回显 Key；未配置 Key 时，AI 端点固定返回 `503`、`AI_NOT_CONFIGURED` 与“AI 名称建议尚未配置。”，页面保持可手工操作。

## 6. 页面行为

### 新订阅向导

地区核验成功后，向导为每个选中默认区商品请求建议，并使用已有的按候选键隔离的中文名称草稿保存结果。输入框显示“AI 建议，待确认”。管理员已经输入或清空过的草稿优先，迟到的异步响应不得覆盖它；多个商品的建议、加载状态和错误都必须相互独立。

确认订阅前仍要求每个商品有非空中文名称。提交仍经过既有服务端官方锚点重验和名称服务裁决；AI 建议只作为浏览器提交的人工候选文本。

### 名称管理页

待补充游戏行增加“生成 AI 建议”按钮。点击后仅为该行请求建议并预填可编辑输入框，显示“AI 建议，待确认”。管理员仍要点击既有“保存中文名称”，并自行决定是否提升为可复用词条。

## 7. 测试与验收

- 适配器测试：只发送允许的官方字段；10 秒超时、未配置 Key、非 2xx、非法 JSON、未知候选键和超长结果均安全降级或返回固定错误，不泄漏 Key 或外部正文。
- API 测试：未认证请求为 401；请求字段严格收窄；结果不能创建或更新游戏/词条/订阅；生产会话与回环本机旁路边界分别覆盖。
- 向导 DOM 测试：地区核验后预填建议、多个商品草稿隔离、人工输入不被迟到结果覆盖、失败仍可手工确认。
- 管理页 DOM 测试：单行建议可编辑、失败提示可读、保存前没有数据库写入、保存后沿用现有服务端重读。
- 安全回归：前端 bundle、JSON 响应、测试快照和普通日志均不含 `DEEPSEEK_API_KEY`；现有官方身份、价格、地区、认证和中文词库测试继续通过。

## 8. 文档同步

PRD、API 设计、数据模型、部署配置说明与旧中文名称规格已经同步：AI 只产生待确认建议、正式名称仍以管理员确认和精确官方身份为准、Key 仅在服务器环境变量中配置；旧规格中“运行时不调用 AI”已更正为“不得自动发布 AI 输出”。

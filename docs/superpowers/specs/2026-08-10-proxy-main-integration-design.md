# 代理功能迁移到当前 Main 设计规格

**状态：** 已实现，待用户确认提交与推送

## 背景

`codex/proxy-main-integration` 已实现无认证 HTTP、HTTPS、SOCKS5 代理设置和统一出站网络层，但它从较早的 PostgreSQL 主线分出。当前 `main` 额外拥有本机开发期免管理员认证和目标价永久删除迁移，不能直接合并该分支。

## 目标

在当前 `main` 上完整提供代理设置，同时保留以下既有行为：

- 本机仅在 `LOCAL_DEVELOPMENT_AUTH_BYPASS=true` 时免管理员认证；NAS 和生产默认仍受认证保护。
- 目标价的 UI、API、领域模型、通知类型和数据库结构保持永久删除状态。
- 设置页可保存无认证 HTTP、HTTPS、SOCKS5 代理，并可执行受控连接测试。
- 任天堂、汇率、已准入第三方、Telegram 与 Playwright 使用统一代理策略；代理故障时遵守既定安全回退规则。

## 方案选择

不执行 Git 的直接 merge。以当前 `main` 为唯一实现基线，逐项移植代理提交 `65a8fe3` 和迁移账本测试 `ef1beb1` 的有效代码、测试和文档，并手工处理与当前主线的重叠。

该方案避免把较早分支中的目标价模型、旧认证假设或过期迁移顺序重新带回主线，也避免 Git 冲突解决时误删除当前主线已验证的本机开发旁路。

## 数据库与迁移

当前 `main` 的 `0001_initial.sql` 是不可变历史，`0002_remove_target_price.sql` 已应用于既有数据库。因此代理设置迁移必须命名为 `0003_proxy_settings.sql`，不得复用代理分支的 `0002_proxy_settings.sql`。

`0003` 只创建或扩展代理设置所需的结构；它不得恢复 `subscriptions.global_target_cny_fen`、`subscription_region_targets` 或 `target-price` 通知事件。迁移和备份恢复合同按字典序记录 `0001`、`0002`、`0003` 三条账本记录。

## 设置与安全边界

代理配置只接受协议、主机和端口，不接受用户名、密码或 URL 内嵌认证。主机、端口和协议都由服务端严格校验，日志、API 响应、迁移、测试与文档不得记录真实代理地址或凭据。

设置页连接测试不保存未提交草稿，只请求服务端固定的安全测试目标。结果区分代理成功、代理失败后直连成功和全部失败，避免把回退误报为代理连通。

## 网络回退规则

幂等读取在代理建立、DNS、TLS 或超时失败时可直连一次；一旦收到目标 HTTP 响应则不再重发。Telegram 等非幂等投递仅在确定请求尚未发出时允许直连，结果不明时不重发。Playwright 的代理失败必须先关闭浏览器、上下文和页面，再启动一次无代理实例。

## 与本机开发认证的组合

认证旁路只影响路由的会话判定，不能改变代理配置验证、数据库连接、出站网络、日志脱敏或生产/NAS 认证。代理设置 UI 在本机旁路开启时可直接访问；旁路未开启时继续要求真实管理员会话。

## 验收

- 代理设置可在设置页读取、校验、保存和测试；无密码协议均覆盖。
- 目标价字符串和结构只允许留在不可变 `0001`、删除迁移及历史设计/测试证据中，当前运行时不得重新出现。
- `LOCAL_DEVELOPMENT_AUTH_BYPASS=true` 的状态、设置和订阅请求可直入；默认配置仍保持真实认证。
- PostgreSQL 迁移、代理回环、API、DOM、Docker、GitHub Actions、类型检查和生产构建全部通过。

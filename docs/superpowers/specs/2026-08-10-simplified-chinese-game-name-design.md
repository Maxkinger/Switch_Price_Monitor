# 简体中文游戏显示名称设计

日期：2026-08-10
状态：待用户审阅

## 1. 目标与范围

仪表盘和订阅详情页中的游戏主标题必须使用经过确认的简体中文常用译名。已有订阅需要一次性进入回填流程；以后新建订阅必须在创建前获得中文显示名称。

本设计只改变游戏名称的管理与展示，不改变官方商品身份、地区映射、官方价格 ID、价格快照、汇率或历史最低价。通知、日报和导出不在本次验收范围；它们保持既有字段与行为，后续如需统一中文化应另行确认。

## 2. 当前问题

当前 `games.name_zh` 同时承载中文展示名和默认区官方标题：订阅确认仅能识别少量本地硬编码词条，未知游戏会把英文或日文官方标题写入该字段。仪表盘与详情页虽复用 `displayChineseGameName`，但该函数只能修正少数标题，因而无法保证全量中文主标题。

官方标题、发行商和商品类型是跨区商品身份的一部分，不能由中文译名代替，也不能通过在线翻译改变。

本设计取代《仪表盘与详情页地区/游戏中文名及官方价格格式设计规格》中“受控前端词表”对游戏名称的限制；其中已经实现的地区中文名和地区价格格式化规则继续保留。

## 3. 方案选择

不采用前端硬编码词表：每新增或修正一个名称都需要发版，且无法让管理员处理争议译名。

不采用运行时机器翻译：常用译名、版本名、DLC、本体与升级包容易被误译，且翻译结果不可审计。

采用“受控名称库 + 单游戏人工覆盖 + 回填队列”：项目只发布已确认的中文名；管理员可对某游戏更正中文显示名，且后续同一官方身份的新订阅可自动复用已确认词条。

## 4. 名称来源与审核规则

名称库按以下优先级收集候选，并且只有人工确认后才可用于正式展示：

1. 发行商或开发商公开的简体中文正式名称，例如官网、公告或官方 Steam 简体中文商店页。
2. 中国大陆正式发行或平台的官方中文标题。
3. 任天堂香港官网的繁体中文标题。它只能作为候选证据；繁简转换后的文本必须人工确认，不能视为常用简体译名。
4. 管理员手动输入并确认的常用简体译名。

每条已确认词条至少记录官方身份匹配键（规范化官方标题、发行商、商品类型）、简体中文显示名、来源类型、证据链接或“管理员确认”标记、确认时间和状态。运行时不抓取站点、不调用 AI 或翻译服务，也不保存任天堂账号、Cookie 或其他凭据。

## 5. 数据模型与匹配边界

新增一个项目自有的中文名称词条存储，以及每个逻辑游戏的简体中文显示名记录。词条用于未来复用；单游戏记录允许管理员对具体游戏覆盖词条结果。

- 词条匹配键必须包含现有的规范化官方标题、发行商和商品类型，不能只按标题匹配，避免把同名本体、DLC、升级包或不同发行商商品混为一谈。
- 单游戏显示名优先级为：管理员覆盖 > 已确认词条 > 待补充状态。
- 英文/日文官方标题继续保留在既有官方字段中，作为采集、跨区核验和审计依据；中文显示名绝不参与 `normalized_name`、官方 URL 或价格 ID 的计算。
- 迁移初期中文显示名可以为空，以便不把历史英文/日文误标为中文。服务层阻止新订阅在缺少已确认中文名时落库；存量数据由回填流程补齐。

为避免 `name_zh` 的历史歧义，实施时应使用语义明确的简体中文显示名字段/DTO，而不是继续把“可能是官方原文”的旧 `name_zh` 直接视为已确认翻译。旧值仅可作为回填候选，不得自动发布。

## 6. 用户流程

### 新建订阅

订阅向导在官方候选和地区映射均已验证后，按官方身份匹配名称库：命中已确认词条时预填简体中文显示名；未命中时显示必填的中文名称确认项。管理员输入或更正后才可完成创建，并将确认结果写入当前游戏显示名与可复用词条。

### 已有订阅回填

管理员从仪表盘进入“中文名称管理”：系统先批量匹配已确认词条；未命中或只具有旧 `name_zh` 候选的订阅进入待补充队列。队列支持搜索、逐条编辑和批量保存，并明确展示官方标题、发行商、商品类型及候选来源，供管理员判定而非由系统猜测。

回填操作必须幂等：再次执行不会覆盖管理员已确认的显示名，不创建或删除订阅、地区商品、价格快照、通知、汇率或历史记录。

### 纠正名称

订阅详情页增加“中文显示名称”管理项，管理员可以修正当前游戏的译名。保存仅更新展示名及其审核元数据；它不会改变订阅启停、地区范围或价格采集身份。若同时更新可复用词条，界面必须明确其会影响将来同一身份的自动预填，而不会静默改写其他已有游戏的人工覆盖。

## 7. 展示与接口边界

仪表盘和详情 API 返回服务端决议后的简体中文显示名；两个页面只渲染这一字段，不再分别调用前端正则词表。这样复选框无障碍标签、卡片标题和详情首行完全一致。

回填尚未完成的存量游戏，在仪表盘和详情主标题显示“待补充中文名称”，而非回退英文或日文；名称管理队列中可以显示官方原文作为仅供管理员辨认的辅助信息。

所有名称管理接口都沿用既有管理员认证和同源 API 边界；请求需要验证订阅/游戏归属、字符串长度、空白文本与重复/冲突的官方身份键。错误响应不回显无关的数据库错误或第三方页面内容。

## 8. 迁移与上线顺序

1. 新增可空的中文显示名与词条存储及审计元数据，不修改已应用的历史迁移文件。
2. 部署服务端匹配、管理 API 与前端管理界面；展示层改为消费服务端决议名称。
3. 创建回填任务：先命中已确认词条，再生成需要管理员确认的队列。任务仅新增/更新名称元数据。
4. 管理员完成待补充队列。以后新订阅由服务层强制具备确认的中文名，防止英文标题重新进入仪表盘和详情页。

迁移和回填前须遵循现有 PostgreSQL 备份与恢复流程。名称元数据的更新可由管理员更正；不涉及删除价格或身份数据。

## 9. 测试与验收

- 先写失败测试，覆盖名称优先级、标题/发行商/类型联合匹配、版本与 DLC 隔离、管理员覆盖与未知名称的待补充状态。
- PostgreSQL 迁移测试验证空库和已有游戏均可升级，旧 `name_zh` 仅成为候选而不会被误当成已确认中文名。
- 服务/API 测试验证新订阅没有确认中文名时不能创建、回填幂等、管理员编辑不改变商品身份与价格关联、未授权请求被拒绝。
- DOM 测试验证仪表盘卡片、复选框标签和详情首行使用同一服务端名称；待补充项不泄露英文/日文主标题。
- 运行相关 Vitest、DOM 测试、TypeScript、生产构建和 `git diff --check`；代码审查同时确认新增中文注释与实现一致。

## 10. 明确不做的事

- 不把翻译 API、AI 或网页抓取结果直接写入正式词库。
- 不把香港繁体标题自动视为简体常用译名。
- 不改变官方商品发现、跨区匹配、价格采集、汇率、历史最低价或地区展示规则。
- 不在本次变更中承诺通知、日报、导出或订阅向导候选搜索结果的文案中文化。
